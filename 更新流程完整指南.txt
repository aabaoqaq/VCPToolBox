VCPToolBox 安全更新指南（旧入口弃用版）

更新时间：2026-09-27
适用项目：F:\VCP\VCPToolBox

本文件现在只规定安全的本机更新入口和保护边界。旧的 `自动更新.bat` 与 `update_with_no_dependency.bat` 已停用：它们只显示提示并返回非零退出码，不会执行 Git、网络、依赖、服务或推送操作。不要把旧 BAT 直接恢复后继续使用；如确需回退，必须使用本批次 manifest 校验后的原文件副本。

## 1. 当前推荐入口

请从 VCPUpdater 执行本机更新，不要直接运行旧 BAT：

```text
F:\VCP\VCPUpdater\start-vcp-updater.cmd
```

也可以在 VCPUpdater 目录执行：

```powershell
npm run start:desktop
```

VCPUpdater 只绑定本机 loopback 地址，VCPToolBox 与 VCPChat 必须分别选择、分别检查、分别应用。当前本机 MVP 流程为：

1. 读取项目分支、HEAD、工作区状态和保护分类；
2. 点击“检测更新”查看上游状态，不下载；
3. 点击“下载并准备更新”后，在仓库外建立临时候选 worktree；
4. 查看候选 commit、文件变化和冲突；
5. 只有候选无冲突、当前工作区干净且基线没有变化时，才允许“应用更新”；
6. 不应用时使用“清理候选”，不要手动删除候选目录或分支。

## 2. 必须停止的情况

遇到下列任一情况，保持原状并记录原因，不要强行覆盖：

- 当前分支不是预期的 `custom`；
- 工作区存在未提交或未跟踪修改；
- 候选包含冲突、删除或无法分类的变化；
- 候选准备后 HEAD、工作区或保护指纹发生漂移；
- 目标路径不在本次明确授权范围内；
- 需要安装依赖、构建原生模块、停止/启动服务、复杂恢复或远程推送。

VCPUpdater 当前 MVP 不会自动安装依赖、不负责构建、不控制 VCPToolBox 服务、不恢复复杂失败现场，也不执行远程 push。不要用旧 BAT 绕过这些阻断。

## 3. 永久保护范围

以下内容不能按文件名猜测、清理或自动迁移：

- 根目录 `config.env` 和所有插件真实配置；
- `Agent/`，尤其是 `Agent/Nova.txt`；
- `TVStxt/`、记忆/日记和其他私人内容；
- `VectorStore/`、SQLite 数据库及 `-wal`/`-shm` 侧车；
- 图片、未知目录、stash 和 `.vcp-runtime/`；
- 官方启动、停止、运行检查链：`一键启动服务器start_server.bat`、`一键关闭服务器stop_server.bat`、`scripts/start-vcp.ps1`、`scripts/vcp-runtime.cjs`、`ecosystem.config.js`；
- 上游通用脚本 `update.bat`、`update.sh`，除非另有单独的对象授权。

禁止使用 `git add .`、`git reset --hard`、`git clean`、`stash pop` 或整仓覆盖来“解决”更新问题。逐文件操作时必须写出明确路径。

## 4. 本批旧入口的处理结果

- `自动更新.bat`：已改为无副作用弃用提示，返回退出码 2。
- `update_with_no_dependency.bat`：已改为无副作用弃用提示，返回退出码 2。
- 两个入口都不会改变当前仓库、联网、安装依赖、操作服务或推送远程。
- 旧入口原件保存在仓库外批次目录，并由 `manifest.json` 记录源路径、字节数、SHA256、Git 跟踪状态和迁移前 HEAD。

## 5. 需要人工确认的高级操作

如果未来需要处理依赖、服务、恢复、其他旧脚本或远程仓库，必须单独写开始记录并明确：项目、文件路径、目标、预计副作用、恢复副本和回滚方式。只授权某个旧入口弃用，不等于授权其他入口、私人配置、stash、服务或远程写入。

真实批次至少应按以下顺序进行：

1. 重新核对分支、HEAD、status、stash、worktree、运行状态和源文件 SHA256；
2. 在仓库外建立逐文件恢复副本和 manifest，并二次校验；
3. 只修改明确授权的文件；
4. 对兼容入口做无副作用验证，对文档做链接和内容复核；
5. 逐文件暂存并创建小的本地提交；默认不推送；
6. 记录结果、未处理状态和可恢复路径。

## 6. 失效备份说明

历史文档曾提到 `F:\VCP\startup-backup-20260923-1516`，当前该路径不存在，不能作为恢复来源。不要创建空目录、复制相似文件冒充备份，或依据该路径执行停服/恢复。当前有效恢复来源以批次 manifest 指向的仓库外副本为准。

## 7. 故障报告格式

遇到失败或中断时，报告以下内容即可：

- 项目、分支、HEAD 和工作区是否变化；
- 候选批次和 manifest 路径；
- 阻断阶段和命令/接口退出码；
- 是否存在冲突或基线漂移；
- 当前可安全执行的下一步。

不要用“更新完成”概括未验证的动作，也不要把旧脚本的行为重新包装成安全流程。
